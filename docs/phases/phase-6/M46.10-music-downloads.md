# M46.10 — Music downloads

**Asked by the user (2026-11-02):** "music downloads in-app and as files in formats with a recording fallback"; "basically everything should be downloadable to the app or externally"; then "get downloads and the rest of your current list working first".

**Relevant docs:** M14 (resolver), M43 (video downloads), M46.1/M46.6 (saving files), research notes in this spec's Decisions.

## Goal
- **Download a song into the app** from any song menu, the Plus popover's neighbours and song tables (several at once):
  - It plays offline from then on, wherever it appears (search, charts, playlists, the queue), because playback swaps in the saved copy by the song's key.
  - Downloads → Music lists the queue with progress, and offers Retry, Remove and Save as a file.
  - Song tables mark downloaded songs.
- **Where the audio comes from:** the stream a source gives (a file over http(s)), resuming partial downloads.
  - YouTube songs (played in YouTube's embed) have no file. Raygun tries other sources for the same song first.
  - When only YouTube has it, the song can be **recorded as it plays**. On Windows, Raygun's own audio is captured through WASAPI process loopback (it includes the webview's processes), from the start of the song to its end, then saved as FLAC.
- **Save as a file:** as downloaded, WAV or FLAC.
  - Desktop: to the Music folder (`Music/Raygun/<artist>/`) or the folder picked in Settings → Downloads.
  - Android: to `Music/Raygun/<artist>/` through MediaStore, or the picked folder.
  - Files carry title, artist, album and cover tags where the format has them.
- **Settings → Downloads:** save downloaded songs as files too (off by default), and the format.

## Design
- **Storage:** `raygun-db::music_downloads` (`local_music_download`, device-local) holds:
  - id, `track_key`, title, artist, album, duration and artwork;
  - the source JSON it came from, and its kind (`file` | `recording`);
  - state (`queued`, `downloading`, `recording`, `done`, `failed`, `needsRecording`);
  - bytes done and total, the file name, the provider and the error.
- **Service** (`raygun-app/src/music_downloads/`):
  - `SongDownloadService` works one song at a time:
    - A source's own URL is used as is.
    - A lookup or YouTube song goes through the resolver, skipping YouTube picks (up to five tries) and marking picks verified or failed, as playback does.
    - The file downloads with Range resume to `downloads/music/<id>/track.<ext>`.
    - With only YouTube left, the row becomes `needsRecording`.
    - A finished download goes into an in-memory index (`track_key` → file).
  - `PlaybackService` asks the index when it loads an item that isn't already a local file, and plays the saved copy instead.
- **Recording** (`record.rs`; Windows only for now):
  - The song is put next in the queue and played.
  - Capture starts at its first playing report and stops when another item loads or playback stops.
  - The capture is float 48 kHz stereo (the engine converts) written to WAV, with leading and trailing silence trimmed, then encoded to FLAC.
  - Android shows that recording needs the desktop app for now (AudioPlaybackCapture needs a MediaProjection prompt each session and a foreground service; noted for later).
- **Formats** (`transcode.rs`): `symphonia` decodes MP3, AAC/M4A, FLAC, Vorbis and WAV; `hound` writes WAV; `flacenc` writes FLAC; `lofty` writes tags. Opus can only be saved as downloaded.
- **Outputs:** a new `Place::Music` (desktop `dirs::audio_dir()/Raygun`; Android `Music/Raygun` in MediaStore Audio).
- **UI:**
  - "Download" and "Remove download" in song menus and the selection bar.
  - Downloads → Music (`music/SongDownloadsList.tsx`).
  - A save sheet with format and place.
  - A downloaded mark in tables.
  - Settings → Downloads: save songs as files, and the format.

## Decisions
- **Where the audio comes from:**
  - A source's own URL downloads as is.
  - Otherwise the resolver is asked up to six times. YouTube picks are skipped (the embed has no file), and each pick is marked verified or failed, as playback does, so the stream cache learns.
  - A pick must carry every word of the song's title (`covers_title`) and name its artist, in the candidate's artist field or its title (`names_artist`). The resolver's `Pick` now carries the candidate's artist. Downloads skip the cache of verified picks (`Exclusions::fresh_only`), which keeps titles only.
  - **Right song skipped:** YouTube Music titles don't name the artist ("SWIM", artist "BTS"), so checking the title alone dropped the right match, and the song failed with "No playable source found" instead of offering to record it.
  - **Wrong song found:** the first Windows run saved Internet Archive's "i can't swim" for BTS's "SWIM". The resolver also now takes 10 points off a candidate that never names the artist (neither in its artist field nor its title). A one-word title no longer matches anyone's song, and playback benefits too.
- **Checking the file:** a downloaded file must decode (symphonia probes it), so an error page saved as `track.mp3` fails instead of playing as silence. Opus and WebM aren't decoded here (no pure-Rust Opus in symphonia 0.6), so their container is enough.
- **Offline playback:** an in-memory index of finished songs (key → file) that `PlaybackService` asks for every load. The queue keeps the original item; the engine gets the saved file.
- **Recording (Windows):**
  - WASAPI process loopback over the main window's WebView2 browser process and its children (its id comes from WebView2's `BrowserProcessId`). The webview's audio service plays YouTube's embed there, so the capture holds only Raygun's sound.
  - The first try used Raygun's own process id with its tree and recorded silence: Windows doesn't carry the loopback down to the browser process, though it is `raygun.exe`'s child. `examples/loopback_probe.rs` captures a process id for a few seconds and shows the difference (Raygun's id: peak 0; the browser process: peak 0.6).
  - Sound is kept only while the recorded item plays: pausing or loading leaves no gap. Recording plays the song at 1×, then restores the speed.
  - Silence is trimmed from both ends and the peak is raised to −0.3 dBFS, so a quiet player volume still gives a full recording.
  - A recording shorter than 60 % of the song is refused (it was skipped or cut off).
  - Android needs AudioPlaybackCapture: a MediaProjection prompt each session and a foreground service. Left for later; the button says recording needs the desktop app.
- **FLAC:** flacenc writes the short last block's size as the stream's minimum block size; symphonia then reads the stream as variable-block and fails. Raygun writes the minimum as the maximum, which is what the format means for fixed-size blocks; ffmpeg reads both.
- **Saving files:**
  - Songs go to `Music/Raygun/<artist>/<artist> - <title>.<ext>` (MediaStore Audio on Android, the Music folder on desktop) or the picked folder.
  - Files are tagged (title, artist, album, cover) with lofty.
  - Settings → Downloads → "Songs saved as" sets the format used when finished downloads are also saved outside the app.
- **Downloads page:** opens on Music; Chapters is a tab like the others (`/manga/downloads` lands there).
