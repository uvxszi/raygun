# M46.43 — Devices: one pairing, and where the sound comes out

## Goal
- **One pairing:** pairing two devices (Settings → Devices, or the Devices button) is the only step. Paired devices sync, can play on each other, and control each other. There's no separate "Remote control" switch, pairing code or "allow this device" question for paired devices.
  - The LAN server (`raygun-remote`) runs while device pairing is on; the web remote page stays for browsers, through the same pairing QR.
  - Connect trusts paired devices (`raygun-db::sync` peers) without asking. Unknown devices still have to pair first.
- **The Devices button** (player bar, desktop and phone) lists:
  - **This device**, with its **audio outputs**: phone speaker, wired headphones, Bluetooth headphones (by name), USB and other outputs; desktop: every output the system lists. Picking one plays there.
  - **Paired devices**: picking one plays there (M46.15); picking This device plays here again. Each device playing its own music is the default.
- **Audio outputs:**
  - Android: `AudioManager.getDevices(GET_DEVICES_OUTPUTS)` with names and kinds, and Media3's `setPreferredAudioDevice` on both players. Changes follow `AudioDeviceCallback`, so new headphones appear at once.
  - Desktop: the webview's `navigator.mediaDevices.enumerateDevices()` (`audiooutput`) and `HTMLMediaElement.setSinkId`, with the Web Audio chain's `AudioContext.setSinkId`.
  - The choice is kept per device (`Settings::audio_output`, by name), so it comes back when that output does.

## Verification
- Android: the Devices sheet lists This device with Automatic and "Phone speaker" (it first showed the emulator's model name; Android names the built-in speaker after the phone, so the speaker and wired headphones now go by what they are); picking the speaker moved the check, and Automatic moved it back.
- Tests: the LocalNetwork, RemoteCard and PlayerBar tests (the remote control under Settings → Devices, the link from the sheet).
- Not checked: Bluetooth or wired outputs (the emulator has neither) and a desktop output change while the app was in use.
