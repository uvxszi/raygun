# M46.3 — Websites, with an ad and popup blocker

**Relevant docs:** M46.2 (the cover cache, for site icons), M38 (the video player activity, a model for a native activity in the `raygun-audio` plugin), ARCHITECTURE §5 (synced tables).

## Goal
- **Websites in Browse:** a list filled by entering an address (and a name).
- **The built-in browser:** a site opens full screen, with back, forward, reload, share and open in another browser, full-screen video, and desktop mode.
- **A blocker on by default:**
  - known ad and tracker domains blocked (a downloaded list, refreshed weekly);
  - popups and pop-unders blocked;
  - jumps to other sites that the page makes by script held, with a notice to go anyway.
- **Per site:** the blocker can be turned off for one site, and the site reopens where it was left.

## Design

### The browser (`WebsiteActivity` in the `raygun-audio` plugin)
- **Its own process** (`android:process=":web"`, `WebView.setDataDirectorySuffix("web")`): the site's cookies, storage and cache are apart from Raygun's own webview, and a crashing site can't take the app down. It is a plain WebView with no JavaScript bridge, so a site can't reach Raygun.
- **Controls:**
  - a slim top bar: close, title and host, a shield showing how much was blocked, reload, and a menu (forward, share link, open in another browser, desktop site, blocker on/off for this site);
  - system back goes back in the page's history;
  - a progress bar while loading;
  - video full screen (`onShowCustomView`) in landscape, with the system bars hidden.
- **Reporting back:** on pause and on close the activity sends `{ id, url, title, blockAds }` in a package-only broadcast. The plugin's receiver passes it to Rust over JNI (`NativeBridge.onWebsite`), which stores the last address and the per-site blocker setting.

### The blocker
- **Ad and tracker domains (network):**
  - Rust downloads the list (default: HaGeZi's Multi NORMAL, domains with their subdomains, about 175,000 entries). It reads plain domain lists, hosts files and simple `||domain^` rules.
  - It writes `web/blocklist.bin`: sorted 64-bit FNV-1a hashes of the domains, about 1.4 MB.
  - The activity loads that into a `LongArray` and checks every sub-resource's host and its parent domains by binary search, in `shouldInterceptRequest` (blocked requests get an empty response).
  - The page's own site is never blocked, and neither is the top-level page itself.
- **Before a list is downloaded,** a short built-in list of the largest ad and pop-under networks is used.
- **Popups:** `onCreateWindow` hands the new window a throwaway WebView and reads its first address. A link to the same site opens in the page; anything else is blocked and counted.
- **Redirects:** a top-level jump to another site that isn't a server redirect is held, with a notice ("Leaving for … · Go"). A tap doesn't prove intent: Chromium counts any navigation within seconds of a tap as tapped, which is how tap-to-redirect ads work. Links to apps (`intent:`, `market:` …) are blocked unless tapped, and even then only offered through Android's chooser.
- **Refresh:** the list is downloaded again weekly when a site opens, or with Update now.
- **Settings → Browse → Websites:**
  - block ads;
  - block popups and redirects;
  - the list (HaGeZi Multi NORMAL, Light or PRO, StevenBlack's hosts, or an address);
  - Update now, with the list's size and date;
  - open sites in desktop mode;
  - clear website data.

### Websites list (`raygun-db::websites`, a synced table)
- **Columns:** `id` (UUIDv7), `name`, `url`, `user_last_url`, `user_block_ads`, `position`, HLC, origin device, tombstone.
- **Where:** Browse → Sources → **Websites** at the end. Add website (a sheet with the address and an optional name, filled in from the host), then tap to open. A row's menu offers Edit, Start over (forget where it was left) and Remove.
- **Site icons:** `https://<host>/favicon.ico` through the cover cache (kept), else the letter tile.

## Out of scope
- **Element hiding (cosmetic filters) and script-level ad blocking:** network, popup and redirect blocking cover what users notice most.
- **Picture-in-picture for site video:** later, with M45's PiP code.
- **Sync of the list:** sync is on hold; the table is ready for it.

## Decisions
- **No preset sites:** Raygun ships no unlicensed streaming site, scraper or source. The feature is neutral: any address can be entered. Sites open as pages in a browser; Raygun doesn't take their streams apart.
- **Its own process (`:web`):** `WebView.setDataDirectorySuffix("web")` keeps cookies, storage and the HTTP cache apart from Raygun's own webview, so clearing website data never touches Raygun's settings in local storage. A crashing page can't take the app down. With no custom `Application`, nothing of Tauri or Rust starts in that process.
- **Talking back:** the browser can't reach Rust in its own process, so it sends a package-only broadcast (the receiver is `RECEIVER_NOT_EXPORTED`, which still takes the app's own other process). The plugin passes it to Rust over a new JNI call (`NativeBridge.onWebsite`).
- **The blocklist file:** sorted FNV-1a hashes rather than a set of strings. 175,760 domains take 1.4 MB as a `LongArray` against tens of MB as `String`s, and the binary search is quick enough for `shouldInterceptRequest`. Both sides use the standard FNV-1a 64 (the Rust test checks the published vector for "a") and sort as signed numbers, as Kotlin searches them.
- **The built-in list (48 big ad and pop-under networks) is merged into the downloaded one,** since some lists (HaGeZi NORMAL among them) leave out a few of those to avoid breaking sites.
- **Redirects are held whatever the gesture:** on the device, a jump 1.5 s after a tap went through as "tapped", because Chromium's user activation lasts about five seconds. That's how tap-to-redirect ads work, so `hasGesture` can't separate them. Every script-driven jump to another site is held with a "Go" notice; server redirects of a navigation already allowed go on.
- **Popups:** the new window gets a throwaway WebView, so its first address can be read. Same-site links (`target=_blank`) open in the page; others are blocked with an "Open" notice.
- **The page's own site** is never blocked by the list, and neither is a top-level page: the list is for what pages load, not for where navigation goes.
- **Site icons:** `https://<host>/favicon.ico` through the cover cache, kept, falling back to the letter tile.
- **Downloading the list:** when a site opens and the list is older than a week, or another list was chosen; also with Update now. Lists are read in three formats: plain domains, hosts files, and `||domain^` rules.

## Verification
- **Checks:**
  - `pnpm lint`, `pnpm type-check`, `pnpm test` (300 UI tests, among them `websites/Websites.test.tsx`: add with the name left to Rust, open, edit, start over, remove, an invalid address, and the Browse settings with the list's size, the popup switch, a list from an address, Update now and Clear website data);
  - `cargo test --workspace` (list parsing in all three formats, the FNV-1a test vectors and the file's layout, address checks and default names, the websites table);
  - `cargo clippy --workspace --all-targets -- -D warnings`;
  - the Kotlin compiles.
- 📱 **On the Pixel_4 emulator, with a local test page** (an ad image from `securepubads.g.doubleclick.net`, a Google Tag Manager script, a cross-site popup button, a same-site `target=_blank` link, and a jump to another site 1.5 s after a tap):
  - **Adding:** Browse → Sources → Websites → Add website saved "Blocker test" (127.0.0.1). Opening it started the browser in its own process (`app.raygun.player:web` next to the app's).
  - **Requests:** the ad image and the tracker script were blocked (shield 2).
  - **Popup:** blocked, with "Popup blocked · Open" (shield 3).
  - **Same-site link:** "Page two" opened in the browser.
  - **Redirect:** with the first rule it went through to example.org (the bug above). After the change it was held with "Leaving for example.org held · Go".
  - **Back** returned to the test page. The menu offered Forward (off when there's nothing to go forward to), Home, Share link, Open in another browser, Desktop site and Block ads on this site.
  - **Reports:** after turning the blocker off for the site and closing, the stored row read `user_last_url = …/page2.html, user_block_ads = 0`. Reopening resumed on page two with the blocker off (shield 0).
  - **Blocklist:** HaGeZi Multi NORMAL downloaded on first open (`web/blocklist.bin`, 1.4 MB). The shield's toast read 175,760 listed, and Settings showed "175,760 sites listed · updated 11/1/2026".
  - **Clear website data:** cleared in the `:web` process (no window, no crash) and showed its confirmation.
  - **Clean-up:** the test page server and port forward were stopped and app data was cleared.
- **Bugs found on the device and fixed:**
  - the redirect rule (see Decisions);
  - the notice was a pale grey pill on light pages (now the bar's dark colour);
  - with the downloaded list, the tracker script loaded (the built-in list is now merged in).
- **Not seen on the device:**
  - full-screen video;
  - desktop mode on a real site;
  - a real ad-heavy site;
  - `intent:` links.
