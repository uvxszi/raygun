## Goal
- **Home** gets Browse all's kinds as rows (`home/MoreRows.tsx`, new `homeSections` ids after Trending): New releases, Popular videos, Popular comics, Popular books (a few working sources' popular pages, the same per-source queries as Search), Popular audiobooks, Charts (tiles), Viral, Genres & moods (tiles), Decades (tiles), Underground. Browse all's tile is `BrowseTile`; audiobook cards are `audiobooks/BookRow.tsx`. Rows load when they come near the window.
- **Cached starts**: the query cache is saved to IndexedDB (`shell/queryPersist.ts`: the 800 most recent answers, a few seconds after changes and when the window hides; volatile answers such as playback, progress and devices are left out) and put back before the app draws; every restored answer counts as out of date, so it shows at once and is asked again in the background. One build's cache only (`__RAYGUN_BUILD__`), at most 7 days old. Answers stay in memory for 3 hours. Image links survive restarts: the proxy binds the port it used last time (`proxy-port` in the data root) and serves `/cover/<token>` from disk for tokens it doesn't know yet.
- **Search from what's seen** (`search/seenBefore.ts`): songs already in the cache (charts, genres, albums, mixes, earlier searches) that answer the query show at once under "Seen before · still searching" until the sources answer; comics, books and videos seen before (Home rows, sources' pages, the library) join the ranked results until every source has answered.
- **Downloads**: a source picker for failed or YouTube-only downloads (`chooseDownloadSource`, the source picker's download mode: answers with a stream of their own, a preview, Download from this → `song_download_use_source`, which tries that stream first and the others after). The "only YouTube" message says what really happened (other sources' files failed, or they had other songs). On desktop yt-dlp saves YouTube's copy as a file (M4A) before any recording is asked for.
- **yt-dlp** (`raygun-app/src/ytdlp.rs`): found in `<data root>/tools/` or on the PATH, else fetched from its GitHub releases and checked against `SHA2-256SUMS`; FFmpeg (for videos above 360p) found the same way or fetched from yt-dlp's FFmpeg builds on Windows. Runs without a console window, one download at a time, to `Downloads/Raygun/YouTube/`. A YouTube address typed in Search shows a card (`youtube/YouTubeLinkCard.tsx`): Play (the embed), Play as music, Download video, Download audio, the download's progress; playlists and channels open on the YouTube extension's pages. Downloads → Exports lists "From YouTube".
- **Browse**: Music is Audio (Browse all's tile, the Search pill, the extensions' kind filter). A second audiobook source, Loyal Books (`extensions/loyalbooks`, built in: popular pages, genres, search among the most popular books, a feed per book); audiobook sources are asked at once and a book two sources share shows once.
- **Updates** (`raygun-app/src/updates.rs`): GitHub's latest release of `uvxszi/raygun`, checked daily (release builds) and from About → Updates. The setup exe and the MSI download the new installer and run it (`/P /R /UPDATE`; `msiexec /passive`), the portable exe opens the release page, Android downloads the universal APK and opens Android's installer (asking for "Install unknown apps" first: `installApk`, `canInstallPackages`, `openUrl` in the plugin, `REQUEST_INSTALL_PACKAGES`). A banner on Home says when a release is out. The repository is a button away.
- **One device link** (`raygun-app/src/device_link.rs`): linking is Connect's question ("Link with <device>?"); both sides swap a `LinkCard` (sync id, key and address; Connect id, address and a token), so each is the other's sync peer (no code) and either plays on the other. Linking turns sharing on (the remote server and the sync server, one switch). Linked devices sync within seconds of a change here (the sync log grows), every 5 minutes, and a sync session runs both ways, so the device that changed is the signal. Unlinking forgets the sync peer and takes the token back. Devices page: Your devices (the switch, linked devices with Play there, Sync now, Unlink, nearby devices with Link, add by address), then this device, what syncs, the log, linking with a code, and the web remote.
- **Test sources**: Settings → Data → Developer → Remove test sources (`dev_remove_test_sources`: the test repository, its `dev.raygun.test.*` extensions and the test addon).
- **Paraline Raygun**: a Raygun-format repository (`raygun/index.json`: Openverse audio), the legal Stremio addons list, and why the bot-checked sources aren't there; Raygun suggests the new repository.
- **v1.0.0**: versions bumped; Windows bundles NSIS and MSI; `.github/workflows/release.yml` builds the portable exe, the setup exe, the MSI and signed APKs (universal and per processor) on a `v*` tag, drafts the release with `docs/releases/<tag>.md`, uploads the files and publishes it. Android signing reads `keystore.properties` (written from the repository's secrets `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`). CI installs `platforms;android-37.0`.

## Verification
- Android (emulator, debug build):
  - Home shows the new rows under Trending: New releases (ListenBrainz), Popular videos (Internet Archive films), Popular comics, Popular books, Popular audiobooks (LibriVox, Loyal Books), Charts, Genres & moods and Decades tiles, Underground (Audius). Viral stays hidden: no source has a viral chart now.
  - Cached start: after a force-stop and relaunch, rows far down Home (Underground's songs and covers) were there within about five seconds, where the first run showed placeholders. The proxy kept its port (`proxy-port`), and the IndexedDB store exists.
  - Browse all's tile and the Search pill read Audio. A typed `youtu.be` address showed its card ("Me at the zoo", jawed, thumbnail), the phone note about downloads, and Play opened YouTube's embed and played.
  - About → Updates: Check for updates reached GitHub. With no release yet, the answer is a note, not an error (changed after this check).
  - Settings → Data → Developer → Remove test sources removed 7 (the test repository, its five `dev.raygun.test.*` extensions, the test addon); none are left in `extensions/`.
- Windows (release build, swapped in while the app was idle on More):
  - Remove test sources removed the same 7; the database lists only the real repositories and addons.
  - Linking: sharing on in both apps; the emulator added the PC by address (`10.0.2.2:8820`) and pressed Link; the PC asked "Link with Android phone?"; after Link both listed the other as linked ("Synced this minute"). The first sync brought the PC's playlists and settings to the emulator.
  - Automatic sync: adding a song to a playlist on the emulator reached the PC by itself within seconds (two sessions, "1 received · 1 changed here").
  - Afterwards both sides were unlinked, the three sessions that changed the PC were undone from its sync log (the emulator's test data doesn't stay in the user's library), and the PC's sharing switch was turned off again, as it was found.
  - Found and fixed: unlinking left the device listed as linked (its network entry kept the sync id), and the asked side didn't remember the token it issued, so unlinking there didn't revoke it. The emulator's NAT makes the PC record the phone's address as its own, so the PC's syncs back to the emulator fail; on a real network the phone's own address is recorded.
- Tests: Rust (`covers_from_an_earlier_start_come_from_disk_and_the_port_is_remembered`, `youtube_addresses_of_every_shape_are_read`, `checksums_and_progress_are_read`, `versions_compare_as_numbers`, `each_install_picks_its_own_file`, `linking_swaps_cards_and_names_the_token_given`, live `loyalbooks_live`), UI (`Updates.test.tsx`, `YouTube.test.tsx`, the Devices, Connect, Local network and Remote card tests rewritten for the one switch). All Rust and UI checks pass.
- Release: the Android key was made with keytool, stored outside the repository (`%USERPROFILE%\.raygun-release`, password in a file, never printed), and set as the repository's secrets with `gh secret set`. `release.yml` builds 64-bit Android only (arm64, x86_64, universal): 32-bit ARM was left out so a crate that doesn't build there can't hold up the release.
