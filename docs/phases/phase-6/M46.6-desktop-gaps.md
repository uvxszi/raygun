# M46.6 — Desktop: saving, sharing, read-aloud and the websites browser

**Relevant docs:**
- M46.1: save and export (`export/output.rs`, `Place`, page actions).
- M33: read-aloud (`tts.rs`, `TtsEvent`).
- M46.3: websites and the blocker (`websites/`, `Blocklist.kt`, `blocklist.rs`).
- M46.4: webview engines on desktop.

## Goal
On Windows (and desktop in general), everything that said "Android only" works:
- **Saving:** files go to the real Downloads and Pictures folders, or a folder picked with the system's folder dialog.
- **Sharing a page** shows it in the file manager; **copying a page** puts the image on the clipboard.
- **Read-aloud** speaks novels with the system's voices.
- **Websites** open in a browser window of their own, with the blocker.

## Design

### Saving and the folder picker
- **Places:** `raygun-paths` gains `user_downloads()` and `user_pictures()` (the `dirs` crate). If there's none, they fall back to `<data root>/exports/`.
  - `Place::Downloads` writes to `<Downloads>/Raygun/…`, `Place::Pictures` to `<Pictures>/Raygun/…`.
  - `Place::Folder`'s `uri` is a plain path on desktop.
  - Portable builds keep their own data next to the exe; exported files land in the usual user folders, as a browser's downloads do.
- **Folder picker:** `pick_folder` uses `rfd`'s folder dialog and returns the path and folder name. `release_folder` does nothing on desktop.

### Sharing and copying
- **Share** writes the file to the share folder as on Android, then shows it selected in the file manager (`explorer /select,`, `open -R`, or `xdg-open` on the folder). The UI calls it "Show in folder" off Android.
- **Copy** decodes the image (`image`: PNG, JPEG, WebP, GIF) and puts it on the clipboard (`arboard`).
- Both crates are desktop-only dependencies.

### Read-aloud
- **The voice:** the webview's `speechSynthesis` with the system's voices. It's a webview engine, like the music and video ones on desktop.
- **Speaking:** Rust still splits the text (`tts::utterances`) and sends `SpeechCommandEvent { speak { items, rate } | stop }`.
- **The engine** (`engine/useSpeechHost.ts`, mounted in the shell):
  - speaks the items in order;
  - reports `{ state, paragraph }` through `tts_report`, in Android's JSON (`speaking` when an item starts, `ended` after the `:end` item, `error`);
  - Rust turns the reports into `TtsEvent`s.
- **Availability:** `tts_available` is what the engine said when it started (`tts_set_available`).

### The websites browser (`websites/desktop.rs`)
- **The window:** each site opens in a Tauri window of its own (`site-<id>`; opening it again focuses it).
  - It has its own browser profile (`<data root>/web/desktop/`), so cookies and storage are kept apart from Raygun's webview.
  - It has no IPC: remote pages get no Tauri capabilities.
  - The title is the page's title, with the number of blocked requests.
- **The menu bar:**
  - ← Back (Alt+←), → Forward (Alt+→), ⟳ Reload (F5), ⌂ Home;
  - a Site menu: Copy link, Open in your browser, Block ads on this site (a check item).
  - On macOS these sit in a menu.
- **The blocker:**
  - **Requests (Windows):** WebView2's `WebResourceRequested` (filter `*`) checks each request's host against the same list (`websites::blocklist::Blocklist`: the FNV-1a file plus the built-in networks). A blocked request is answered with 403. The page's own site and the top-level page are never blocked.
  - **Popups** (`on_new_window`): a link to the same site opens in the window; others are blocked and counted.
  - **Navigation:** cross-site navigations go on. The desktop can't tell a click from a script, so holding them would hold real links too.
- **Reports:** where the page is (`on_page_load`) and the per-site switch are stored when the window closes, through the same path as Android's reports.
- **Clear website data:** closes the browser windows, then deletes the profile. If WebView2 still holds it, it's deleted at the next start.

### Readers on wide windows
- **The scrolling manga reader** (the webtoon mode): one column, the screen's width on phones as before and at most 768 px on wide windows. Whole printed pages are the paged mode's job, which fits the screen already.
- **Novels** are 20 % larger on windows 1024 px and wider (`--reader-scale`), in a column one step wider.

## Out of scope
- **Request blocking on macOS and Linux** (popups are still blocked there): Windows is the desktop in use.
- **Downloads from websites:** WebView2's default download prompt stays.
- **Choosing a voice for read-aloud:** the system's default voice is used.

## Decisions
- **User folders for exports:** portable builds keep Raygun's data next to the exe. Saved files go to the usual user folders, as a browser's downloads do. `raygun-paths` resolves those folders with `dirs`, and falls back to `<data root>/exports/` when the system has none.
- **Desktop "share" saves and shows:** there is no share sheet, and the share folder is a cache that's cleared. So on desktop the page action is "Show in folder": the page is saved to Pictures/Raygun and selected in Explorer.
- **Copying decodes in Rust** (`image` + `arboard`, desktop-only). The clipboard gets a bitmap any app can paste.
- **Read-aloud is a webview engine.** `speechSynthesis` uses the system's voices with no native code, and fits how desktop plays music and video. Rust still decides what is read and in what pieces, and gets the same reports as on Android.
- **Each site is its own window.** It has its own WebView2 profile, so cookies stay apart from Raygun's. It has no capabilities, so pages can't call Raygun.
  - **The menu bar:**
    - Back, Forward, Reload and Home are plain buttons, because Windows prints a top-level item's shortcut into its label ("BackAlt+Left").
    - The shortcuts live on the same actions in the Page menu.
  - **Blocking (Windows):** requests are blocked with WebView2's `WebResourceRequested`, using the same hashes as Android (`websites::blocklist::Blocklist` reads the file `Blocklist.kt` reads).
  - **Popups** are kept to the site with `on_new_window`.
  - **Script jumps aren't held:** the desktop can't tell a click from a script, so holding cross-site navigations would hold real links too.
- **More's tab list:** tabs that were never added made More long on a fresh install, so it now lists only shown tabs that don't fit and default tabs that were hidden (M46.5's rule, changed).

## Verification

- 🖥️ **On Windows (portable release build):**
  - **Websites:** Browse → Websites → Add website saved a local test page. Opening it made its own window:
    - the title read "Blocker test — 2 blocked": the doubleclick ad image and the googletagmanager script were blocked;
    - the cross-site popup made it 3;
    - the same-site `target=_blank` link opened page two in the window;
    - closing on page two and reopening resumed there;
    - Home went back;
    - the Page menu listed the shortcuts, Copy link, Open in your browser and the blocker switch;
    - the blocklist (HaGeZi Multi NORMAL, 175,760) downloaded on first open;
    - Clear website data deleted the 70 MB profile.
  - **Page actions** (right-click in the manga reader, Android's long-press):
    - Save page wrote `Pictures\Raygun\<title>\… - Chapter 1 - 1.png` (296 KB);
    - Copy page put a 720×818 image on the clipboard;
    - Show in folder opened Explorer. The first build showed the cache share folder; it now saves to Pictures and selects the file there.
  - **Read-aloud:** Alice's Adventures in Wonderland (Gutenberg), chapter I. The speaker button showed (the engine reported voices). Starting it highlighted the first paragraph, the highlight moved to the second, and Stop ended it.
  - **Readers:** the webtoon reader filled the whole width before; the novel text was small.
    - **The first fix** fitted images up to 1.6 times as tall as wide to the window's height, and kept taller ones wider. It failed: this webtoon's slices are short enough to pass for pages, so they showed at their small natural size in a narrow column. The scrolling reader is the webtoon mode, so it now uses one 768 px column for everything.
    - The test title then opened in the paged mode, where a page fits the screen (a 720-wide slice shows about 436 px wide). Zoom and scale choices for both modes come in M46.7.
  - **Clean-up:** the test site, the saved page and the local test servers were removed.
- **A test fixed on the way:** "lists updates by day" put yesterday's update 24 hours back. On 2026-11-01, the day clocks went back (25 hours), that was still today, so it now uses the calendar's yesterday.
- **Not seen on Windows:**
  - the folder dialog (picking a folder for downloads);
  - an export to Downloads.
