## Goal
- **Search:**
  - Several sources' results appear as one list of best matches by default, each card naming its source. "By source" shows a row per source, as before.
  - Music search offers Songs, Artists and Albums.
    - Songs: best matches or by source.
    - Artists open the artist page.
    - Albums open an album page (play, shuffle, download all).
  - A source finder sits beside the source chips when there are many.
- **Failing sources go last** in Browse → Sources and in Search, behind a setting:
  - Settings → Browse → Sources, and the ⋮ menu in Browse.
  - Sources that failed lately say so.
- **Desktop panels stay:**
  - The rail shows covers only below 1024 px.
  - The Now playing panel narrows to at most 30 % of the window instead of disappearing.
  - The full player keeps the bar visible and sizes its video by the window's height.
- **Song tables:** column dividers follow the pointer live, from the column's left edge, and move with the arrow keys.
- **Placeholders** use the cover grid's size.
- **Novels:** paragraph indents (reader quick settings and Settings → Reader).
- **Sources' identity:** a default User-Agent setting, as Mihon has; first-party extensions for open databases keep naming themselves.
- **Per-source data:** cookies kept per extension, and "Clear cookies and data" in a source's menu. A source's website opens in Raygun's browser from its menu.

## Decisions
- **Ranking:** `titleScore` gives 100 for the exact title, 80 when it starts with the query, 60 when every word appears, less for some words. Ties keep each source's own order, and with nothing typed the sources take turns. Results are ranked as sources answer, so slow sources add to the list instead of holding it back. "By source" is remembered per medium on this device (`raygun.search.grouped.<medium>`).
- **Music search:** `music.metadata` providers may add `searchArtists`, `searchAlbums` and `album`.
  - Deezer (a new `catalogue` provider) and MusicBrainz (release groups with Cover Art Archive covers) implement them.
  - Artists with the same name from several sources show once.
  - An album page plays, shuffles or downloads its songs as lookups, which the resolver finds streams for like any chart song.
- **Failing sources:**
  - A source that errors or times out is remembered for three days on this device (`raygun.sourceHealth`, a UI concern like the search history), and leaves the list once it answers.
  - The order is a setting (`failingSourcesLast`, on by default), also in Browse's ⋮ menu.
- **Panels:**
  - The rail and the Now playing panel stay at every desktop width.
  - Below 1024 px the rail's library shows covers only, and the side panel takes at most 30 % of the window.
  - The full player starts below the app bar (`--app-bar`), so the bar's Back, search and window buttons stay usable. Its video is sized by the window's height, so it never pushes the controls off screen.
  - The readers' own top bars also start below the app bar; it hid them before (found while checking indents).
- **Column dividers** (landed with M46.9's commit): a divider sits on the left edge of the column it resizes, the column follows the pointer while dragging, and the arrow keys move it by 16 px. The old one measured from the other edge, so columns moved the wrong way.
- **Placeholders** (also with M46.9): source rows draw their loading placeholders in the cover grid's own size instead of a fixed larger one.
- **Royal Road in Browse:** Browse's hidden search field sent its old text back to the app bar on desktop, so a new query from Browse was replaced by the previous one. On desktop the app bar owns the query.
- **User-Agent:**
  - Sources already introduced themselves as a desktop Chrome, unless an extension names itself.
  - Only first-party extensions for open databases send "Raygun/1.0": MusicBrainz, ListenBrainz, LRCLIB, Radio Browser, MangaDex and Apple's feed. Their API rules ask clients to name themselves (MusicBrainz requires it).
  - Settings → Browse → Sources → User agent replaces the default for every source's requests (JS extensions and Shosetsu scripts) that don't name their own, like Mihon's "Default user agent string". It is live (`raygun_net::set_user_agent`).
- **Cookies:**
  - Each extension has its own jar (`cookie_store` behind reqwest's `CookieStore`).
  - Lasting cookies are saved to `extensions/.data/<id>/cookies.json`; session cookies stay in memory.
  - A `Cookie` header an extension sets itself wins.
  - "Clear cookies and data" in a source's ⋯ menu deletes the jar and `raygun.storage`, then reloads the extensions.
- **Websites:** an extension's site is its manifest's `website` or a Shosetsu script's `baseURL`. "Open the website" shows it in Raygun's own browser (the blocker applies; nothing is stored in the user's site list).
- **Captchas and Cloudflare (not built):**
  - Raygun doesn't solve captchas or bot checks, neither in the background nor by moving cookies from the browser into a source after the user passes a check there.
  - Those checks exist to keep automated clients out, and getting a source past them is circumventing them.
  - A source that a site blocks shows its error; the site can still be read in Raygun's browser.
- **Royal Road, Scribble Hub, Webnovel (not added to Paraline):**
  - Royal Road and Scribble Hub answered Raygun's requests with HTTP 403 (their bot protection), and Webnovel returned no results.
  - A working copy would have to get past those protections, so Paraline doesn't carry them.
- **One running copy (desktop):** `tauri-plugin-single-instance`. Starting Raygun again focuses the open window instead of a second copy writing to the same database.
