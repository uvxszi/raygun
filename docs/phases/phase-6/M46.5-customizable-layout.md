# M46.5 — Customizable layout

**Asked by the user (2026-11-01):** "i want you to make it very customizable, so you can add and move around tabs and options and such, similar to mihon i think it does that".

**Research (reference apps, 2026-11-01):**
- **Mihon:** the bottom tabs are fixed (`HomeScreen.kt` `TABS`). Its customization is in library categories (drag to reorder, per-category sort in `category.flags`, tab and count toggles) and in sources (pin, disable, language filter).
- **Aniyomi:** comes closest for navigation. `NavStyle` moves one tab into More, there is a start screen, categories can be hidden (eye icon), and player buttons are custom (ordered, one favourite on screen, the rest in a sheet).
- **CloudStream:** providers are pinned in an ordered list (`user_pinned_providers`), poster badges toggle, and player buttons are shown or hidden.
- **Ordering in the UI:**
  - drag handles (Mihon, Aniyomi; `sh.calvin.reorderable`);
  - up/down arrows (TachiyomiAT, Shosetsu).
- **Storage:** ordered lists rewritten after each move. Mihon's unordered string sets are why its pins can't be ordered.

**Relevant docs:** M42.1 (the shell, Settings categories and `prefs.tsx` rows), M39 and M46 (library categories and layouts), M46.4 (the player bar).

## Goal
Raygun's screens become lists the user arranges, going further than any reference app:
- **Navigation:** reorder tabs, hide them, and add more; a start screen.
- **Library:** the media tabs and Audio's chips.
- **Home:** its sections.
- **Browse:** its tabs and its source sections.
- **More:** its entries.

Everything can be reset to the default.

## Design

### Storage (`LayoutPrefs` in raygun-model, `Settings::layout`, one stored row)
- **Lists:** each surface is an ordered list of `{ id, visible }`: `tabs`, `libraryMedia`, `audioViews`, `homeSections`, `browseTabs`, `browseSections`, `moreEntries`.
- **Known entries:** the `LAYOUT_*` constants hold each surface's entries in their default order.
- **Normalizing** (`LayoutPrefs::normalized`, run whenever the row is applied):
  - drops ids Raygun no longer has, and duplicates;
  - puts each missing entry after the one that precedes it by default (Mihon's filter-chain merge), so an update never loses the user's order.
  - The UI fills an older row the same way (`layout/layout.ts`).
- **Validation:**
  - More stays shown, plus at least one other tab;
  - Settings stays in More;
  - Search stays in Browse;
  - at least one library tab and one Audio view stay shown.
- **Start screen:** `StartScreen` gains the tabs that can be added (Watch, Music, Comics, Books, Podcasts, Search, Updates, Downloads).

### Navigation tabs (`shell/navTabs.ts`)
- **What can be a tab:** Home, Library, Browse and More (shown by default), and Watch (Library → Videos), Music, Comics, Books, Podcasts, Search, Updates, Downloads and Settings.
- **Phones:** five fit. When more are shown, the first four and More stay in the bar.
- **The desktop side rail** shows every shown tab.
- **More's "Your other tabs":** tabs that are hidden, or that don't fit on a phone, are listed at the top of More (Aniyomi's NavStyle, for any number of tabs).
- **The current tab** is the closest match: Watch (Library with `media=video`) beats Library on Library → Videos.
- **Start screen:** any shown tab (Settings → Appearance).

### Screens
- **Library:**
  - the media tabs follow the list; the first one shown is where Library opens;
  - Audio's chips follow theirs, and the first one shown is Audio's default view;
  - a hidden tab or chip still shows while it is open.
- **Home:** sections in order. "Nothing to pick up yet" stays first while there is nothing.
- **Browse:** tabs in order. Without a tab in the address it opens Sources, or the first tab shown. Sources' sections (Movies & series, Manga, Novels, Websites) follow their list.
- **More:** a single list in the user's order, after "Your other tabs".

### Editing (`layout/LayoutEditor.tsx`, `pages/LayoutSettingsPage.tsx`)
- **Where:** Settings → Appearance → Layout lists every surface with what it shows. Each opens `/settings/layout/<surface>`.
- **Each row:**
  - a drag handle (`@dnd-kit/sortable`: pointer, touch and keys);
  - up and down buttons;
  - an eye switch, or a lock for entries that always show;
  - Reset to default for the whole list.
- **Saving:** a change shows at once and saves. Rust's refusal is shown.
- **Shortcuts:**
  - Library's ⋮ → Edit library tabs;
  - Home's ⋮ → Edit Home;
  - Browse's ⋮ → Edit Browse;
  - More's ⋮ → Edit More and Edit tabs.

## Out of scope (later)
- **Pinned sources and hiding sources** (Mihon, CloudStream): with source management in M53.
- **Tapping the open tab again** for quick actions (Mihon): the tab bar's behaviour is unchanged.
- **Player and reader buttons** (Aniyomi's custom buttons, CloudStream's switches): with M45's follow-ups and M50.
- **Per-profile layouts:** profiles don't exist yet.

## Done-check
- **Rust:**
  - a stored layout keeps its order, drops unknown ids, and puts new entries in place;
  - refusing to hide More, Settings, Search or every tab;
  - Watch as a tab and as the start screen.
- **Vitest:**
  - add, move and hide tabs, with the bar following, and Reset;
  - More can't be hidden;
  - tabs past five listed in More;
  - the start screen opening Watch with its tab current;
  - the first library tab shown opening first;
  - Home's order and a hidden More entry;
  - the Layout screen's summaries.
- 🖥️ **On Windows:** dragging rows; the side rail following.

## Decisions
- **More than Mihon:** Mihon's tabs are fixed, so "similar to mihon" was taken as the spirit: everything Raygun lists can be ordered and hidden, and screens can be added as tabs.
- **One row, lists of `{id, visible}`:** stored as ordered lists rather than sets, so the order survives (Mihon's pins can't keep theirs). The lists are merged with the known entries on every load, so new features appear without resetting anyone's layout.
- **What can't be hidden:**
  - More leads to everything else, so it can't be hidden;
  - Settings stays in More;
  - Search is Browse's reason to exist.
  - Everything else, Home and Library included, can be hidden.
- **Phones keep five tabs** (Material's limit); the rest move to More rather than shrinking the bar.
- **The current tab is decided by the bar,** not by each link: TanStack's `Link` counts any link whose search is a subset of the address as active, which marked Library and Audio current on every library page. Links now only count exact matches, and the bar picks the closest tab. Library's media tabs had the same problem and were fixed the same way.
- **Drag and buttons:** dragging is quickest with a mouse or finger. The up and down buttons make every move possible with keys and screen readers, and they are what the tests use.

## Verification
- **Checks:**
  - `pnpm lint`, `pnpm type-check`, `pnpm test` (321 UI tests; `layout/Layout.test.tsx` covers the Done-check list);
  - `cargo test --workspace` (`settings::tests::layouts_*`: merging an older row with an unknown id and a missing tab; refusing to hide More, Settings or Search, every tab, or every library tab; Watch as a tab and the start screen);
  - `cargo clippy --workspace --all-targets -- -D warnings`.
- 🖥️ **On Windows (portable release build, maximized):**
  - **Home → ⋮ → Edit Home:** listed the four sections with handles, arrows and eyes. Dragging "Your music" by its handle with the mouse to the top saved it, and Home then showed Your music above Continue watching.
  - **More:** with the default tabs, it listed Watch, Music, Comics, Books, Podcasts and Search under the tabs that aren't in the bar. Updates, Downloads and Settings weren't listed twice.
  - **More → ⋮ → Edit tabs:** listed all 13 with More locked. Showing Watch and Comics and dragging Watch above More turned the rail into Home, Library, Browse, Watch, More, Comics.
  - **Watch:** opened Library → Videos with Watch highlighted and Library not.
  - **Reset to default** restored the tabs and Home. The test entries from M46.4 were removed from Continue watching, so the app is back to how the user left it.
- **Not checked on a device:** touch dragging on Android (the emulator is off while the user tests desktop). dnd-kit's pointer sensor handles touch, and the handle has `touch-action: none`.
