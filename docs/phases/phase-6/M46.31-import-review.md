# M46.31 — Import you can review and fix

## Goal
- **Review before importing** (Import songs sheet, after reading a link, a list or screenshots; `collections/ImportReview.tsx`):
  - Each row's title and artist are editable in place. Leaving a changed field searches for the song again.
  - **Add a song:** a form at the end (title and artist) adds a row, matched like the others.
  - **Rearrange:** rows drag (dnd-kit) and have up/down buttons; the playlist keeps that order.
  - **Sources:** each matched row names its source. When more than one source has the song, **Sources (n)** opens the list:
    - each source's title, artist and length;
    - **Preview**, which plays it in the normal player;
    - **Use this**.
- **Import doesn't wait:** "Make a playlist" works while matching is still running.
  - Rows still matching are saved as `pending`.
  - After saving, Rust keeps matching them (`ImportService::save`). Each found source fills every saved copy of the song (`collections::set_track_source`), and `ImportEvent(playlist id)` refreshes the lists.
- **Songs nobody has are kept**, marked **Unavailable** (`local_track_unavailable`, migration 0027):
  - Lists show "Unavailable · Find a source…" under the title (`music/useUnavailable.ts`, `TrackTable`).
  - Playing one looks it up again. A play that starts clears the mark (`DurationService::on_playback`).
- **Find a source…** is in every song's menu, not only for imports, to replace a poor stream (`music/SourcePickerSheet.tsx`):
  - it searches every source and ranks the answers;
  - each has a preview and **Use this** (`track_assign_source`), which fills every saved copy of the song and clears its mark.

## Decisions
- **Candidates:** matching keeps up to five candidates per song (`import::find_songs`), one per source, each scoring at least the import minimum, best first. The sources list costs no new search.
- **Background matching** runs one song at a time after the playlist is saved, so sources aren't flooded. It dies with the app; songs left unmatched stay as lookups and resolve when played.
- **Unavailable is a mark, not a state of the row:** a found source clears it everywhere, because the mark is per track key.

## Verification
- **Checks:** as M46.29; `collections/Import.test.tsx` covers editing, adding, reordering, Sources (n) with two answers from one source, importing while matching and the unavailable mark. `raygun-resolver` tests `artist_agrees`, and `raygun-db` tests `set_track_source`.
- **Windows:**
  - A pasted list showed the review, "Finding the songs in your sources: 0 of 3".
  - "Make a playlist" made it at once (pinned in the sidebar), and the background matching filled albums, lengths and covers within about 30 s.
  - A made-up song ("Qwzx Imaginary Band – Not A Real Song 48213") was matched to a stranger's track. Imports now need the artist to agree (`raygun_resolver::artist_agrees`, in `find_songs` and `find_song`).
- **Android (after that fix):**
  - The made-up song stays unmatched: "Found 1 of 2… kept as unavailable".
  - Maple Leaf Rag showed "3 sources" with previews and Use this.
  - The playlist lists the made-up song as "Unavailable · Find a source…". Find a source searched every source, and Use this cleared the mark.
- **Found and fixed while checking:**
  - Two answers from one source (MusicBrainz) both said "In use". The review now tracks the picked candidate (`Row.chosen`).
  - Merged results in Find a source had no source name ("This song plays from now"). They're looked up in the sources' own lists, with a fallback sentence.
  - A picked source kept an earlier guessed length. A pick now takes the stream's length (`set_track_source(…, picked)`).
  - Deleting a playlist sat on its page for seconds, because the page refetched the deleted list with retries, so it looked like the first tap did nothing. It now leaves the page before lists refresh (`useDeletePlaylist(after)`).
