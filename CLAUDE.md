# Raygun

All-in-one multimedia app (music, video, movies/TV, anime, manga, light novels) built on Tauri v2 (Rust + React/TS). License AGPL-3.0-only. Identifier `app.raygun.player`.

## Read first

- `docs/ROADMAP.md`: phases and milestones; work happens one milestone at a time.
- `docs/phases/phase-N/MNN-*.md`: the spec for the milestone in progress. Write one before starting a milestone.
- `docs/ARCHITECTURE.md`: read only the sections the milestone spec lists.
- `docs/reference-notes.md`: findings from the reference repos in `reference/` (git-ignored). Check here before re-exploring a repo.

## Layout

- `apps/raygun/`: React UI (`src/`) and the thin Tauri shell (`src-tauri/`, plus `gen/android`).
- `crates/raygun-app`: service wiring + Tauri commands. `crates/raygun-model`: types shared with TS.
- `packages/bindings`: TS generated from Rust by tauri-specta. Never edit it; run `pnpm bindings`.
- `crates/raygun-resolver`: stream matching and ranking (pure). `raygun-app` has the `ResolverService` (cache, providers) and the per-load `resolution::Tracker` that `PlaybackService` follows for lookups and fallback.
- `crates/raygun-mcp`: the MCP server's transport (streamable HTTP on 127.0.0.1:8810–8819, bearer token, Host/Origin checks, JSON-RPC dispatch). The tools live in `raygun-app/src/mcp.rs`; Settings turns the server on (off by default).
- `crates/raygun-remote`: the LAN remote (web page + JSON/SSE API on 0.0.0.0:8820–8829, QR pairing with one-time codes). The backend lives in `raygun-app/src/remote.rs`; off by default. Verify on the emulator with `adb forward tcp:8820 tcp:8820` and the browser pane (loopback, so Android 17 never blocks it; a real LAN connection is `adb emu redir add tcp:<pc port>:8820`, which arrives from 10.0.2.2).
- `crates/raygun-sync`: device sync (Noise XX channel, pairing, half-duplex protocol, mDNS discovery); storage and merge live in `raygun-db::sync`. Test against a PC with `cargo run -p raygun-sync --example peer -- <dir> serve` (the emulator reaches it at 10.0.2.2). Since M46.47 linking devices (Connect's question) turns it on and pairs without a code; see `device_link.rs`.
- Raygun on the web (`docs/WEB.md`): `apps/raygun/src/web/` answers the bindings in the page (`ipc.ts` stands in for Tauri; `core/` settings, collections, playback with `raygun-playback` ported; commands without one get empty answers made from the bindings' types, `web-build/commandAnswers.ts`), keeps data in IndexedDB, syncs with the apps over WebRTC (`raygun-sync::web`: an ICE-lite listener on UDP 8840–8849; the link code carries the browser fields) and runs Raygun's JS extensions in sandboxed iframes (`web/extensions/`; starter and app-only sources in `webSources.ts`; comics, books and videos through `core/catalog.ts`, titles in the `titles` table; `setRemoteHandler` in `core/index.ts` is where a linked app answers what the page can't). `pnpm --filter @raygun/app build:pages` (`vite.pages.config.ts`, base `/raygun/`), published by `.github/workflows/pages.yml`; Rust's settings defaults reach it as `packages/bindings/src/settings-defaults.json` (`pnpm bindings`). Platform `web`. A linked app can be its back end (WEB.md "The app as a back end"): data channel 1 (`raygun-sync::remote`), commands through Tauri's invoke path with a denylist (`raygun-app/src/web_remote.rs`), proxy links as `__remote/…` answered by the service worker (`web-build/remoteWorker.ts`, `web/remote/`); songs resolve there (`resolve`, the web core's `setRemoteFinder`) and videos the page starts play in its own player (`RemoteViewer`, checked in `video::open_player`/`update_player`); test with `peer … serve --web --remote`.
- Manga (M24): `raygun-db::titles` (episodic library), `raygun-ext-host::manga` (`manga.source` calls), `raygun-app/src/manga.rs`; covers and pages load through the stream proxy's `/image/` route with the source's headers.
- Novels (M31): `novel.source` = the manga catalogue calls plus `passage`; `raygun-ext-host::novel` turns passage HTML into text blocks (no source HTML reaches the webview). `raygun-app/src/catalog.rs` holds what manga and novels share; the UI's manga pages take a `medium` (`manga/medium.ts`). First-party source: `extensions/gutenberg`.
  - Book text structure (after v1.9.0): italics/bold/code are `Part::Styled`, list items and indented lines (`<dd>`, `<blockquote>`) `Item` (→ `TextBlock::Paragraph.list`, the mark drawn from `data-marker`), tables of data `Table` (`novel/tables.rs` `is_data_table`: ≥2 rows and columns, no code blocks/tables/headings in cells, not a gallery; layout tables are read through), a cell's pictures `Part::Image`, a formula alone in its paragraph a display block. UI: `novel/TextParts.tsx` (marks the spoken sentence across parts), `novel/TableBlock.tsx`, `novel/spoken.ts` (`tableSpeech`: a row a sentence, cells after their column's header). Downloads keep the answer (`source.json`, `passage_source`) and parse it again on read. Live: `open_books_live_wikibooks_latex`.
  - Book text: `<pre>` is a code block (`PassageBlock::Code`/`TextBlock::Code`: lines as written, the highlighter's `language`; running prose in `<pre>` stays paragraphs), drawn by `novel/CodeBlock.tsx`, skipped aloud unless it reads as verse (`novel/code.ts`). `novel/bookText.css`: long words wrap, code and wide formulas scroll in their own boxes, the text never scrolls sideways. A PDF book's contents are its whole outline (`novel::pdf_contents`, each bookmark with its chapter), listed alike in its page and text views (`novel/PdfContentsSheet.tsx`; the text view opens a bookmark at the heading it names, `novel/pdfContents.ts`).
- EPUB and speech (M33): `raygun-app/src/epub.rs` reads books (lenient parsing, chapters split at TOC anchors as `path#start#end`); imports unpack to `downloads/books/<sha256>/` with `/local`-safe names, as `local.epub` novels. Novel chapters download through the manga queue (`downloads/novel/…/passage.json`). Text-to-speech is `Speech.kt` in the `raygun-audio` plugin, reporting over JNI to `raygun-app/src/tts/` (`TtsEvent`).
- Reading aloud (after v1.8.0): Rust keeps the session (`raygun-app/src/tts/`: sentences from `raygun_ai::tts::sentences`, engine ids `<run>:<sentence>`, Pause/Resume on the sentence and word, places per chapter in `local_meta` `reader.readAloud.marks`, `TtsUpdate` with the sentence's UTF-16 range); Android's notification is `ReadAloudService.kt` (controls come back as `{"control"}` reports). Downloaded voices (Settings → AI → Reading aloud, `Settings::read_aloud`): Piper and Kokoro models (catalogue `kind` `tts`, `.tar.bz2` archives unpacked by `models::Unpack`) run by sherpa-onnx 1.13.8's C API (`raygun_ai::tts::sherpa`, loaded with libloading from the per-platform `runtime` model fetched with the first voice; 2.x dropped espeak-ng), synthesized a few sentences ahead (`tts/voices.rs`) and played by `SpeechClips.kt` or `useSpeechHost`'s clip player. Live: `SHERPA_RUNTIME=<runtime dir> PIPER_MODEL=<dir> KOKORO_MODEL=<dir> cargo test -p raygun-ai --release -- --ignored speaks_live --nocapture`.
- PDF books and chapters: `raygun-net::pdf` (hayro, shared; `Document` draws pages, reads each page's text into paragraphs and the outline) behind the proxy's `/pdf/<token>/<page>?w=` (`PdfStore`: `l<hex path>` tokens for files under downloads, `w<hash>` for registered web documents fetched into the page cache's `pdf/`; drawn pages kept in the page cache; hayro crates build optimized in debug). Imported PDFs are `local.pdf` books (`books/<sha256>/document.pdf`, chapters `pages:<first>-<last>` from the outline, `NovelService::import_pdf_file`: uploads, Local Files, Open with). Sources answer `{ pdf }` from `pages`/`passage` (`PdfRef`, `#raygun-pdf` mark on a page address); downloads keep `document.pdf`. `NovelChapter.pdf` → `novel/PdfPagesView.tsx` over `manga/reader/PageReader.tsx` (the comic reader's body; drawn widths `drawnPages.ts`), text view `novel_pdf_text`, search `novel_pdf_search`, bookmarks as Contents.
- Formulas in book text: `raygun-ext-host::math` (MathML rebuilt from an allowlist, TeX → MathML by `pulldown-latex`, a linear text and words for speech) → `PassageBlock::Rich`/`Math`, `TextBlock::Math` and paragraph `parts` (with `sup`/`sub`). UI `novel/MathFormula.tsx` (`mathml.ts` checks the markup again; Latin Modern Math in `novel/math.css`).
- Reading aloud (after v1.8.1): a book is read in the language chosen in the reader (`tts_set_language`, per title in `local_meta` `reader.readAloud.languages`), else its EPUB's or source's (`DictionaryService::book_language`), else `raygun_ai::tts::language::guess` over the chapter; long foreign paragraphs get their own voice only with `ReadAloudPrefs::detect_languages` (`language::foreign_passage`). Roman numerals in titles become numbers in `Utterance::spoken` (`raygun_ai::tts::numerals`, `roman_*` settings; English words, digits for other languages); the text shown and highlighted stays as written. Settings changes reach the reading live (`settings::apply_live` → `tts::settings_changed`: restart from the sentence, the clips' volume at once via `ttsClipVolume`/`SpeechCommand::Volume`). UI `novel/readAloud/` (`ReadAloudOptions` in the reader's Read aloud tab and the bar's options sheet, `useFollowReading`, `textOffset` for taps and selections).
- Read-aloud voices (after v1.9.1): the catalogue's Piper and Kokoro voices are full precision (sherpa-onnx's int8 builds measured 2–6× slower, their quantized convolutions run mostly on one thread; Kokoro keeps the id `kokoro-multi-lang-int8`; outdated voice folders go at start, `AiService::outdated_of_kind`). Threads are the fast cores less one (`raygun_ai::tts::threads`, 4 at most on phones); `tts/voices.rs` makes speech ahead until 20 s waits (6 sentences at most), long sentences in pieces sized to what the voice makes before the waiting speech runs out (`sentences::piece_end`, `piece_limit`, a short one first), and keeps 24 MB to play again. Pickers list voices not downloaded with their size (`novel/readAloud/voiceChoice.ts`); choosing one is `tts_use_voice` (`tts/choice.rs`: downloads it, then chooses it unless another choice came meanwhile). "Letter I" is a numeral only as a title (a heading, or a line it starts). Measure with `speed_live` (`SHERPA_RUNTIME`, `PIPER_MODEL`/`KOKORO_MODEL`, `TTS_THREADS`); live headings check `frankenstein_live` (raygun-app).
- Reading aloud (after v1.9.4): English abbreviations are said in full in `Utterance::spoken` (`raygun_ai::tts::abbreviations`: Saint/Street and Doctor/Drive by the words around, titles only before names, Jr./Inc. after them, labels before numbers, e.g./i.e./etc.); sentences don't end at them (`sentences.rs` `TITLES`, `MAY_END` + `abbreviations::stop_ends`). `ReadAloudPrefs::split_at_commas` (off): downloaded voices cut long sentences only at ; : and dashes, at a comma only while under `SHORT_LEAD` waits (`voices::cuts_at_commas`, `piece_end(.., commas)`). Speed is `NovelReaderPrefs::tts_speed` in hundredths, 50–300 (old `ttsRate` tenths migrate in `settings::migrate_row`); the bar's `novel/readAloud/SpeedButton.tsx` steps on a tap and shows speeds and a slider on a hold or right click.
- Shosetsu (M32): `raygun-ext-host::shosetsu` runs Shosetsu's Lua novel sources (manifest runtime `shosetsu`, net `*` = any public host). `select` is a Jsoup-compatible selector engine, `dom` the Jsoup-like DOM, `http` the OkHttp-like API, `runtime` the sandboxed Lua 5.2 state (one thread per script), `prelude.lua` kotlin-lib's helpers. Shosetsu repositories (`index.json` with `scripts`) install through the normal Extensions screen; live check: `cargo test -p raygun-ext-host -- --ignored shosetsu_official` (`SHOSETSU_SCRIPTS=shosetsu.en.x,…`). M46.9.1: a script whose hash differs from its index installs if it starts with a metadata line; `shosetsu_survey` runs every script of the official index (or `SHOSETSU_DIR`, a checkout such as `reference/shosetsu-extensions`) through listing → passage. Fixed scripts for legitimate sites go to Paraline Raygun (`uvxszi/paraline-raygun`, checked out beside this repo; `tools/build_index.py` rewrites its index), keeping their ids so they arrive as updates.
- Kodi add-ons: `raygun-ext-host::kodi` runs video and music plugins (`xbmc.python.pluginsource`) unchanged in RustPython 0.6 (compiled in, `host_env` off; `third_party/rustpython-host_env` patched for Windows): `package` installs a plugin with the `script.module.*` libraries it imports (its repository, then Kodi's), `python` is the sandbox (Kodi paths mapped to the extension's folders, `_raygun.fetch` over Raygun's HTTP, SQLite, a 45 s run), `lib/` the Python side (`xbmc*`, stand-ins for `requests`, `urllib3`, `socket`, `ssl`, `inputstreamhelper`), `catalog` maps folders onto `video.source` (folders are `MangaCard::folder`, listed by the source page's `folder=`) and `music.metadata`/`music.stream`. Indexes list compiled add-ons once per system: `index::one_each` keeps one per id (this system's `<platform>`, then Python 3, then the highest version in Kodi's order), zips and icons at its `<path>`. Live: `kodi_media_ccc_live`, `kodi_somafm_live`, `kodi_official_survey`; doc `docs/extensions/formats/kodi.md`.
- `crates/raygun-ai` (M34): the encrypted secrets store (`secrets.db`, key in `local_meta`), the model catalogue/downloader (`src/catalog.json`, files pinned by SHA-256) and translators (Claude over raw HTTP, OpenAI-compatible, DeepL). App side: `raygun-app/src/ai.rs`, Settings → AI.

On-device models' pills and sort: `settings/ai/modelUse.ts`; Continue watching's download lines: `watch/continueMenu.ts` `downloadItems`.

- Content filter and languages (M35): `ContentFilter` in `raygun-ext-host` (the `showNsfw` setting; hides `nsfw`-rated extensions' providers, `raygun.content.showNsfw()` for extensions, `nsfw` on listings, adult genres in `catalog::is_adult`; the library leaves such titles out while it is off, `catalog::split_hidden`, and says so: `library_hidden` → `manga/HiddenEntries.tsx`, a "3 hidden entries" note with a sheet). - Crash logs and safe start: `raygun-app/src/crash_log.rs` (records in `logs/crashes/`: the panic hook, `crash_log_write` for the page's errors; Kotlin's `CrashLog.kt` adds uncaught exceptions (handler installed by every activity and service), the renderer gone (once per death), Android's exit reasons with tombstones (`recordExits`: at each process start, `MainActivity.onResume`, and `crashRecordExits` before Rust lists; deduped by pid and moment); About → Crash logs `pages/CrashLogsPage.tsx`). A start that never ran 20 s (`.starting`), the renderer gone (`OfflineGateClient.onRenderProcessGone` → `RaygunErrorActivity`, process `:crash`) or the error screens' Start in safe mode make the next start safe: no query-cache restore (`window.__RAYGUN_SAFE_START__`), queues and the last queue wait (`crash_log::when_healthy`), extensions load one at a time; sources at work both times two starts stopped are held back (`ExtensionHost::set_held_back`, `extension_hold_back`). The extension host reports loads and calls through `raygun_ext_host::activity`. Page errors: `shell/ErrorScreen.tsx` (`RootErrorBoundary`, `RouteError`). JNI entry points catch panics (`android.rs` `guarded`); QuickJS runs with `disable-assertions`. How to get logs: `docs/CRASH_LOGS.md`.

- Local network access (M41.1): Android 17 apps targeting SDK 37 need `ACCESS_LOCAL_NETWORK` to reach private, link-local or `.local` hosts and to accept LAN connections; without it TCP times out. `raygun-net::local_network` says which hosts are local; `raygun-app/src/local_network.rs` (`LocalNetwork`) asks the `raygun-audio` plugin and fails requests to local hosts at once without it (`check`). The UI explains and asks first through `network/useLocalNetworkGate` (Addons page, remote switch).
- Offline Mode and Data Saver (`Settings::network`, `NetworkPrefs`, device-only): `raygun_net::network_mode` holds the switches. Every `client_builder` client goes through `GateLayer` (no connection but loopback while offline); senders ask `check`/`allows` first, so failures are `IssueKind::OfflineMode` ("Offline mode is on"), never counted against sources (`fanout::Health`), addons, video sources, streams or songs (`mark_unplayable`, import marks); the proxy serves only this device and caches (503 otherwise), covers never fetch or revalidate, bodies stop with `until_offline`, loops wait in `wait_online` (lookups: app `network_mode::wait_for_lookups`). App: `raygun-app/src/network_mode.rs` (`start_with` before services, `apply` from `apply_live`, `went_offline`: downloads held by `device_state::downloads_held` and requeued, never failed; remote, sync, Connect and casting leave the LAN; playback passes over songs not on the device), `network_status`/`network_set_offline`, `NetworkStatusEvent`; Android's main webview loads nothing remote (`OfflineGate.kt`, set around wry's client in `MainActivity.setContentView`).

- Save and export (M46.1): `raygun-app/src/export/` (`ExportService`: jobs that queue missing chapters through the normal download queue, then write CBZ+ComicInfo `cbz.rs`, streaming PDF `pdf.rs`, EPUB/text `book.rs`, joined HLS with AES-128 `video.rs`; `output.rs` makes files in `Download/Raygun`, `Pictures/Raygun` or a picked folder; `pages.rs` saves/shares/copies reader pages; `names.rs` is Mihon's file-name rules). ## Android tooling gotchas (for agents)

- Run `tauri android dev|build` in a real terminal tab (Terminal panel), not a headless shell. Without a TTY, the CLI's device prompt loops forever (it once wrote a 13 GB log), and `adb shell` blocks on an open stdin pipe.
- Only one Tauri Android command can run at a time. A stuck one shows `Blocking waiting for file lock on Android` in the next. Find leftover `tauri.js android ...` node processes and stop them.
- Verify on the emulator with `adb install -r .../app-universal-debug.apk`, `adb shell am force-stop app.raygun.player`, a relaunch, then `adb exec-out screencap -p`. App logs: `adb shell "run-as app.raygun.player cat logs/<file>"`.
- Env for headless runs (user variables; set them per command in a shell that predates them): `ANDROID_HOME=N:\Toolchains\android-sdk`, `NDK_HOME=N:\Toolchains\android-sdk\ndk\28.2.13676358`, `ANDROID_USER_HOME=N:\Toolchains\android-user`, `GRADLE_USER_HOME=N:\Toolchains\gradle`, `CARGO_HOME=N:\Toolchains\cargo`, `RUSTUP_HOME=N:\Toolchains\rustup`, `TEMP`/`TMP=N:\Raygun\cache\temp`.

## Rules

- Domain state and logic live in Rust services. The UI calls generated `commands.*` and holds UI-only state.
- Platform priority: Android first (`Pixel_4` emulator), Windows desktop second. Build or verify desktop only when the task calls for it; keep the code cross-platform.
- Desktop builds must be portable: never call OS app-dir APIs or `tauri-plugin-store`. Go through `raygun-paths` (M02).
- Synced tables use UUIDv7 ids, HLC timestamps and tombstones (ARCHITECTURE §5, §10).
- Adapted code from a reference repo keeps a header naming the source repo and its license.
- TS: `type` over `interface`, `const Component: FC<Props>`, no one-letter names. Tests use RTL queries and userEvent, and mock only the bindings/IPC layer.
