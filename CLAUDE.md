# Raygun

All-in-one multimedia app (music, video, movies/TV, anime, manga, light novels) built on Tauri v2 (Rust + React/TS). License AGPL-3.0-only. Identifier `app.raygun.player`.

## Read first

- `docs/ROADMAP.md`: phases and milestones; work happens one milestone at a time.
- `docs/phases/phase-N/MNN-*.md`: the spec for the milestone in progress. Write one before starting a milestone.
- `docs/ARCHITECTURE.md`: read only the sections the milestone spec lists.
- `docs/reference-notes.md`: findings from the reference repos in `reference/` (git-ignored). Check here before re-exploring a repo.

## Layout

- `apps/raygun/`: React UI (`src/`) and the thin Tauri shell (`src-tauri/`, plus `gen/android`).
- `crates/raygun-app`: service wiring + Tauri commands. `crates/raygun-model`: types shared with TS.
- `packages/bindings`: TS generated from Rust by tauri-specta. Never edit it; run `pnpm bindings`.
- `crates/raygun-resolver`: stream matching and ranking (pure). `raygun-app` has the `ResolverService` (cache, providers) and the per-load `resolution::Tracker` that `PlaybackService` follows for lookups and fallback.
- `crates/raygun-mcp`: the MCP server's transport (streamable HTTP on 127.0.0.1:8810–8819, bearer token, Host/Origin checks, JSON-RPC dispatch). The tools live in `raygun-app/src/mcp.rs`; Settings turns the server on (off by default).
- `crates/raygun-remote`: the LAN remote (web page + JSON/SSE API on 0.0.0.0:8820–8829, QR pairing with one-time codes). The backend lives in `raygun-app/src/remote.rs`; off by default. Verify on the emulator with `adb forward tcp:8820 tcp:8820` and the browser pane (loopback, so Android 17 never blocks it; a real LAN connection is `adb emu redir add tcp:<pc port>:8820`, which arrives from 10.0.2.2).
- `crates/raygun-sync`: device sync (Noise XX channel, pairing, half-duplex protocol, mDNS discovery); storage and merge live in `raygun-db::sync`. Test against a PC with `cargo run -p raygun-sync --example peer -- <dir> serve` (the emulator reaches it at 10.0.2.2). Since M46.47 linking devices (Connect's question) turns it on and pairs without a code; see `device_link.rs`.
- Manga (M24): `raygun-db::titles` (episodic library), `raygun-ext-host::manga` (`manga.source` calls), `raygun-app/src/manga.rs`; covers and pages load through the stream proxy's `/image/` route with the source's headers.
- Novels (M31): `novel.source` = the manga catalogue calls plus `passage`; `raygun-ext-host::novel` turns passage HTML into text blocks (no source HTML reaches the webview). `raygun-app/src/catalog.rs` holds what manga and novels share; the UI's manga pages take a `medium` (`manga/medium.ts`). First-party source: `extensions/gutenberg`.
- EPUB and speech (M33): `raygun-app/src/epub.rs` reads books (lenient parsing, chapters split at TOC anchors as `path#start#end`); imports unpack to `downloads/books/<sha256>/` with `/local`-safe names, as `local.epub` novels. Novel chapters download through the manga queue (`downloads/novel/…/passage.json`). Text-to-speech is `Speech.kt` in the `raygun-audio` plugin, reporting over JNI to `raygun-app/src/tts.rs` (`TtsEvent`).
- Shosetsu (M32): `raygun-ext-host::shosetsu` runs Shosetsu's Lua novel sources (manifest runtime `shosetsu`, net `*` = any public host). `select` is a Jsoup-compatible selector engine, `dom` the Jsoup-like DOM, `http` the OkHttp-like API, `runtime` the sandboxed Lua 5.2 state (one thread per script), `prelude.lua` kotlin-lib's helpers. Shosetsu repositories (`index.json` with `scripts`) install through the normal Extensions screen; live check: `cargo test -p raygun-ext-host -- --ignored shosetsu_official` (`SHOSETSU_SCRIPTS=shosetsu.en.x,…`). M46.9.1: a script whose hash differs from its index installs if it starts with a metadata line; `shosetsu_survey` runs every script of the official index (or `SHOSETSU_DIR`, a checkout such as `reference/shosetsu-extensions`) through listing → passage. Fixed scripts for legitimate sites go to Paraline Raygun (`uvxszi/paraline-raygun`, checked out beside this repo; `tools/build_index.py` rewrites its index), keeping their ids so they arrive as updates.
- `crates/raygun-ai` (M34): the encrypted secrets store (`secrets.db`, key in `local_meta`), the model catalogue/downloader (`src/catalog.json`, files pinned by SHA-256) and translators (Claude over raw HTTP, OpenAI-compatible, DeepL). App side: `raygun-app/src/ai.rs`, Settings → AI.
- Content filter and languages (M35): `ContentFilter` in `raygun-ext-host` (the `showNsfw` setting; hides `nsfw`-rated extensions' providers, `raygun.content.showNsfw()` for extensions, `nsfw` on listings, adult genres in `catalog::is_adult`). Locales are `apps/raygun/src/i18n/locales/<tag>.json`, loaded on demand; `pnpm i18n:import` copies exact-match translations from `reference/` apps (see `docs/TRANSLATING.md`).
- Podcasts (M37): `raygun-db::podcasts` (feeds, episodes, progress, device-local downloads), `raygun-app/src/podcast_feed.rs` (RSS/Atom via quick-xml), `raygun-app/src/podcasts.rs` (`PodcastService`; follows playback through `on_playback`, called by `PlaybackService` with every state change), `podcast.directory` capability (none ships since v1.2.0; without one, podcast search points to Browse → Extensions). UI: Library → Audio → Podcasts (a chip) and `/podcast?id=`.
- UI shell (M42.1): tabs Home · Library · Browse · More (`shell/navItems.ts`; Watch lives in Library → Videos, `/watch` redirects there). Every screen starts with `shell/TopBar` (title, back, icon actions, `OverflowMenu`, search mode); sub-views use `shell/Tabs`; inputs go in `shell/Sheet` dialogs or the top bar, never at the end of a list. Title screens use `shell/TitleHero` and a floating `ResumeFab`. Browse (`pages/BrowsePage.tsx`) is where content is found: its header is the search bar (typing switches to its Search tab, `search/SearchPanel.tsx`), then Sources by kind (Stremio addons with catalogues open `/watch/addon`) and Extensions. The Library holds only saved and added content; its empty states link to Browse → Search; More (`pages/MorePage.tsx`) links everything else. Settings is a category list (`settings/sections.ts`) with one screen per category (`pages/SettingsSectionPage.tsx`) built from `settings/prefs.tsx` rows (`PrefSwitch`, `PrefChoice`, `PrefSlider`, `PrefLink`); every option is a field of the Rust `Settings` (accent, start screen, grid columns, cover style, badges, resume, watched point, seek step, subtitles...).
- Watch (M38): `VideoPlayerActivity.kt` in the `raygun-audio` plugin (Media3 ExoPlayer: HLS/DASH, headers, subtitles, gestures, PiP), opened through `NativeAudio::video_open`; reports come back over JNI (`NativeBridge.onVideo`) to `raygun-app/src/video.rs`, which saves progress (`raygun-db::video`) for Continue watching. UI: Library → Videos and the player.
- Stremio addons (M41): `raygun-app/src/stremio/` (`protocol` = the addon HTTP transport, pure; `StremioService` = addons, catalogs, meta, streams, subtitles, play), addons stored in `raygun-db::stremio`. Progress keys are `stremio:<type>:<videoId>`. Video subtitles load through the proxy's `/subtitle/` route (an empty track when a file fails). UI: `/watch` rows, `/watch/title`, `/watch/catalog`, `/watch/addons`; Search → Movies & series. Check on the emulator with a local addon at 10.0.2.2 (after allowing local network access) or through `adb reverse`.
- Local network access (M41.1): Android 17 apps targeting SDK 37 need `ACCESS_LOCAL_NETWORK` to reach private, link-local or `.local` hosts and to accept LAN connections; without it TCP times out. `raygun-net::local_network` says which hosts are local; `raygun-app/src/local_network.rs` (`LocalNetwork`) asks the `raygun-audio` plugin and fails requests to local hosts at once without it (`check`). The UI explains and asks first through `network/useLocalNetworkGate` (Addons page, remote switch).
- Library (M39): media tabs Audio (music and podcasts, as chips) / Comics (`medium` manga) / Books (`medium` novel) / Videos in `LibraryPage` (labels `library.tabs.*`; `library.media.*` stays the name of each kind elsewhere); manga and novel categories in `raygun-db::categories` (commands take a `medium`); filters, sort and genre tags are computed in the UI by `manga/libraryFilters.ts` over `MangaLibraryEntry`. Audio → All (`library/MusicOverview.tsx`) is the default view; `library/AudioViewChips.tsx` is Audio's chip row.
- Save and export (M46.1): `raygun-app/src/export/` (`ExportService`: jobs that queue missing chapters through the normal download queue, then write CBZ+ComicInfo `cbz.rs`, streaming PDF `pdf.rs`, EPUB/text `book.rs`, joined HLS with AES-128 `video.rs`; `output.rs` makes files in `Download/Raygun`, `Pictures/Raygun` or a picked folder; `pages.rs` saves/shares/copies reader pages; `names.rs` is Mihon's file-name rules). Rust can't open `content://`, so the `raygun-audio` plugin's `Storage.kt` creates each file (MediaStore or SAF tree) and hands over a detached descriptor (`createOutput`/`finishOutput`, `pickFolder`, `shareFile`, `copyImage`). `Settings::save` (`SavePrefs`) sets where finished downloads are also saved. Chapter downloads retry (2/4/8 s or `Retry-After`) and resume from kept pages (`raygun-net::images`). UI: `export/` (ExportSheet, ExportsList = Downloads → Exports, PageActionsSheet on a long press in the reader), Settings → Downloads.
- Websites (M46.3): sites added by address (`raygun-db::websites`, a synced table) open in `WebsiteActivity` (`raygun-audio` plugin) in its own process `:web` (its own WebView data directory, no bridge to Raygun). The blocker: `raygun-app/src/websites/blocklist.rs` turns a list (default HaGeZi Multi NORMAL, refreshed weekly) into `web/blocklist.bin`, sorted FNV-1a hashes that `Blocklist.kt` searches in `shouldInterceptRequest`; popups go through a throwaway WebView, and script-driven jumps to other sites are held with a notice. The browser reports `{id, url, blockAds}` in a package-only broadcast that the plugin passes to Rust (`NativeBridge.onWebsite` → `websites::install`). Settings: `Settings::websites` (`WebsitePrefs`). UI: Browse → Sources → Websites (`websites/WebsitesSection.tsx`), Settings → Browse → Websites.
- Customization (M46.7): `Settings` holds `accent_color`, `cover_width` (`manga/coverGrid.ts`), `manga_reader` (`MangaReaderPrefs`, `manga/readerDisplay.ts`), `player_view` (`PlayerViewPrefs`, `player/playerView.ts`), `scrollbars` and `motion` (root `data-` attributes styled in `styles.css`). Menus opened from a button pass it as `Sheet`'s `anchor` and become a `shell/Popover` beside it on wide windows. The full player (`player/PlayerSheet.tsx`) has views `artwork`/`lyrics`/`queue` (`playerUiStore.sheetView`) and lays out side by side or stacked; positions between engine reports come from `player/useLivePosition`. YouTube's embed replies carry the load they're about (`token`), so late reports about the previous video are dropped. Extension installs go through `extensions/installQueue.ts` (one at a time, no confirmation; `EntryInfo` shows access in a popover).

- Sound (M46.12): `Settings::sound` (`SoundPrefs`: 10 bands in tenths of a dB, preamp, bass, reverb, balance, mono, normalization target, crossfade). - Customizable layout (M46.5): `Settings::layout` (`LayoutPrefs`: ordered `{id, visible}` lists for `tabs`, `libraryMedia`, `audioViews`, `homeSections`, `browseTabs`, `browseSections`, `moreEntries`; `normalized()` merges with the `LAYOUT_*` defaults, `validate()` keeps More, Settings and Search). UI: `layout/layout.ts` (same merge, `LAYOUT_DEFAULTS`), `useLayout`, `layout/LayoutEditor.tsx` (dnd-kit plus up/down and eye), `pages/LayoutSettingsPage.tsx` (`/settings/layout/<surface>`). Tabs come from `shell/navTabs.ts` (`NAV_TABS`, `useNavTabs`: five on phones, the rest in More; the closest match is current). Links in tab bars use `activeOptions={{ exact: true, includeSearch: true }}` and set `aria-current` themselves.
- Desktop gaps (M46.6): exports go to the system's Downloads/Pictures folders (`raygun_paths::user_downloads`/`user_pictures`) or a folder picked with `rfd`; desktop "share" saves to Pictures and selects the file in Explorer, copy decodes with `image` into `arboard`. Read-aloud on desktop is the webview's `speechSynthesis` (`engine/useSpeechHost.ts`) driven by `SpeechCommandEvent`, reporting through `tts_report`. The websites browser on desktop is `websites/desktop.rs`: one Tauri window per site (`site-<id>`, its own profile `web/desktop`, no capabilities), a menu bar, popups kept to the site, and on Windows WebView2 `WebResourceRequested` answering listed hosts with 403 (`websites::blocklist::Blocklist`).
- Image cache (M46.2): covers, posters, thumbnails, icons and addon logos go through the proxy's `/cover/<token>` (`ImageLinks::cover`, or `kept_cover` for library titles, followed podcasts, installed extensions and addons), served from `raygun-net::cover_cache` (`cache/covers`, with `keep/` never evicted and `meta/` holding ETag/Last-Modified for background revalidation). Reader pages stay on `/image/` and the page cache. Tokens are SHA-256 (`proxy_image_token`). `raygun-app/src/caches.rs` (`Caches`) builds both caches from `Settings::cache` (`CachePrefs`), applies changes live, reports `storage_usage`/`storage_clear`, and sorts kept covers 30 s after start. Store source addresses, never proxy links (`ImageLinks::original`). Extension icons come from repository indexes (`RepoEntry.icon`, Shosetsu `imageURL`). UI: Settings → Data → Storage (`settings/StorageSettings.tsx`).
- Library depth (M46): title marks (list, favorite, pin) are `title.user_list`/`user_favorite_at`/`user_pinned_at` (`TitleMark`, `raygun-db::titles::set_mark`); a category's own layout/sort is `category.user_display`. Bulk actions are `raygun-app/src/library_actions.rs` (`library_*` commands take a `medium` and title ids: lists, favorites, pins, read, remove, categories, download next, continue, duplicates). Layout lives in `Settings::library_display` (`LibraryDisplayPrefs`). UI: `MangaLibraryView` (tabs by category or list, selection), `LibraryItems` (four layouts), `LibrarySelection` (selection bars and sheets), `LibraryFilterSheet` (Filter/Sort/Display), `libraryQuery.ts` (the search language), `TitleListActions` and `useDuplicateCheck` on title pages. Local comics: `raygun-app/src/comics.rs` (CBZ/ZIP + ComicInfo, unpacked to `downloads/comics/`), source `local.comics`; files reach Rust through chunked uploads (`uploads.rs`, `upload_*` commands, `manga/useImportComics.tsx`).
- Video sources (M42): `video.source` = the manga catalogue calls (details add `type`, `year`, `cast`, `directors`; `episodes` with `season`) plus `servers` and `videos` (aniyomi's hosters: each server resolves on its own). `raygun-ext-host::video` parses them; `raygun-app/src/video_sources.rs` (`VideoSourceService`) wraps a `Catalog` of kind `video` (titles store `media_type`/`year`), orders links by the `preferredVideoQuality` setting and plays through `video::play` (progress key `source:<sourceId>:<episodeId>`). UI: Watch rows per source, `/watch/source` (the shared source page, `medium` `video`), `/watch/video` (title, episodes, server picker), Search → Movies & series, Settings → Playback. First-party source: `extensions/internet-archive/src/films.ts`.
- Video library (M43): saved movies and series are titles of kind `video` (Stremio ones have source `stremio` and remote id `<type>:<id>`, stored and refreshed by `StremioService`); watching progress is mirrored onto their episodes by progress key (`raygun-app/src/video_library.rs`), and library updates (`MangaService::run_update`) cover them. Downloads: `raygun-app/src/video_downloads/` (`VideoDownloadService`, one at a time, queue in `raygun-db::video_downloads`, files in `downloads/video/<id>/`; `hls.rs` picks the variant and rewrites keys, maps and segments to local names); `video::play` plays a finished download under the same key through the proxy's `/local/` route. UI: Library → Videos (`MangaLibraryView` with `medium` `video`), `/updates` and `/downloads` (tabs), `/watch/history`.
- Playback sessions (M44): `raygun-app/src/video_session.rs` (`VideoSessions`) plays a title's episodes: the player (`VideoPlayerActivity`, `singleTask`) opens at once, links resolve in the background (all servers / all addons, the last-used source and `bingeGroup` first), a failed link falls back to the next. Rust sends `videoUpdate` messages (`load`, `episodes`, `sources`, `loading`, `error`); the player answers with `request` reports (`next`, `previous`, `episode`, `source`, `autoplay`, `ready`), handled in order through one queue in `video.rs`. Episodes played this way resume through an `EpisodeRef`; finishing one puts the next in Continue watching at 1 ms. Title pages: tap = session, long press or Choose a source = picker.
- Player controls (M45): the player draws its own overlay. In the `raygun-audio` plugin: `PlayerControls.kt` (top bar, previous/play/next, `DefaultTimeBar` with chapter marks, lock/rotate/speed/chapter/aspect/PiP, skip button), `PlayerGestures.kt` (brightness/volume swipes with dimming and `LoudnessEnhancer` boost, swipe to seek, configurable double taps, hold for speed), `PlayerTracks.kt` (`OffsetTextRenderer` = subtitle delay via `ForwardingRenderer`, track picking by language/prefer/skip words, `SecondSubtitles` parses a subtitle file for the second track), `PlayerSheets.kt`, `PlayerTools.kt` (screenshots, another app with MX/VLC/mpv extras, PiP actions), `PlayerPrefs.kt`. Settings live in `Settings::video_player` (`VideoPlayerPrefs`, one `serde(default)` row; UI `pages/PlayerSettingsPage.tsx`, `/settings/player/<page>`). Each title remembers speed, aspect, tracks, subtitle delay and intro length in `local_value` `video.playerState.<group>` (`VideoRequest::group`); the player saves with `state`/`prefs`/`brightness` requests and asks for AniSkip with `duration` (`raygun-app/src/aniskip.rs`; `VideoRequest::anime`). Chapters come from extensions' `timestamps` (`VideoRequest::chapters`). Check the Kotlin quickly with `gradlew :tauri-plugin-raygun-audio:compileDebugKotlin` in `apps/raygun/src-tauri/gen/android` (about 25 s).
- Search (M40; inside Browse since M42.1's third pass): `/browse?tab=search&type=all|music|podcast|video|manga|novel|library&q=` (`/search` redirects there); manga/novel global search (`catalog_global_search`) and source filters (`filters()` in the SDK, `SourceFilter`/`FilterValue` in the model, `catalog_filters`/`catalog_search`).
- `crates/raygun-ext-host`: extension host (QuickJS via rquickjs on one host thread, host API in `src/prelude.js`). Each JS extension's runtime has a driver (`AsyncRuntime::drive`, spawned on the host's `LocalSet`); without it, two calls into one extension at once could leave one waiting forever (M46.45). `third_party/rquickjs-sys` is a vendored copy that adds Android bindings.
- `extensions/`: first-party extensions (TS on `@raygun/sdk`), compiled into the app from their committed `dist/` bundle (`raygun-app/src/extensions.rs`); rebuild with `pnpm build:extensions` (a test fails when a bundle is stale). An installed copy in the data root's `extensions/<id>/` overrides the built-in one.
- `repo/`: Raygun's official extension repository (`index.json` + `packages/`), served from GitHub raw and seeded into every install. Generated by `raygun-ext pack`; never hand-edit it.
- `packages/sdk`: `@raygun/sdk` (extension types/helpers, MIT) and the `raygun-ext` CLI (`init`, `build`, `dev --android`). Debug app builds poll `extensions/` and hot-reload; run `pnpm dev:android` inside an extension folder (in a Terminal-panel tab) to push every save to the emulator.
- Extension guide: `docs/extensions/` (a page per kind, host API, manifest, repositories). `raygun-ext init --kind` copies `packages/sdk/templates/<kind>` (legal sites; the guide's examples are tested against them); `validate` (`lib/manifest.mjs`, `lib/check.mjs`, `lib/typecheck.mjs`); `test` runs `raygun-ext-host`'s `call` example, whose `review` module reads answers with the app's parsers; calls per kind are `lib/kinds.json`.
- `packages/nuclear-compat`: converts Nuclear player plugins (TS) into Raygun extensions at install. The converter and shim run in QuickJS; the bundle is committed at `crates/raygun-ext-host/assets/nuclear-converter.js`. Rebuild it with `pnpm --filter @raygun/nuclear-compat build` (a test fails when it is stale). Bump `CONVERTER_VERSION` (in `convert.ts` and `raygun-ext-host::nuclear`, kept equal) when the shim gains something installed plugins should get: the catalogue then offers them again. Conversions reach any public host besides their own, and may register any Nuclear kind (M46.9.1).
- `plugins-mobile/raygun-audio`: native Android audio engine (Media3 in a `MediaSessionService`; reports reach Rust over JNI). The app shell must depend on each mobile plugin directly, or Tauri won't include its Android module.

## Commands

```bash
pnpm install
pnpm dev                 # desktop
pnpm android:dev         # Android emulator (needs ANDROID_HOME and NDK_HOME)
pnpm lint && pnpm type-check && pnpm test
cargo test --workspace   # includes a check that bindings are current
cargo clippy --workspace --all-targets -- -D warnings
pnpm format && cargo fmt --all
pnpm bindings            # regenerate TS bindings after changing commands/types
cargo test -p raygun-ext-host -- --ignored   # live extension tests (network)
pnpm trim:target         # drop stale incremental caches and old workspace-crate builds (pnpm dev / android:dev run it first)
pnpm repo:publish        # pack first-party extensions into repo/ (the official repository; bump versions first)
```

## Android tooling gotchas (for agents)

- Run `tauri android dev|build` in a real terminal tab (Terminal panel), not a headless shell. Without a TTY, the CLI's device prompt loops forever (it once wrote a 13 GB log), and `adb shell` blocks on an open stdin pipe.
- Only one Tauri Android command can run at a time. A stuck one shows `Blocking waiting for file lock on Android` in the next. Find leftover `tauri.js android ...` node processes and stop them.
- Verify on the emulator with `adb install -r .../app-universal-debug.apk`, `adb shell am force-stop app.raygun.player`, a relaunch, then `adb exec-out screencap -p`. App logs: `adb shell "run-as app.raygun.player cat logs/<file>"`.
- Env for headless runs: `ANDROID_HOME=%LOCALAPPDATA%\Android\Sdk`, `NDK_HOME=...\Sdk\ndk\28.2.13676358`.

## Rules

- Domain state and logic live in Rust services. The UI calls generated `commands.*` and holds UI-only state.
- Platform priority: Android first (`Pixel_4` emulator), Windows desktop second. Build or verify desktop only when the task calls for it; keep the code cross-platform.
- Desktop builds must be portable: never call OS app-dir APIs or `tauri-plugin-store`. Go through `raygun-paths` (M02).
- Synced tables use UUIDv7 ids, HLC timestamps and tombstones (ARCHITECTURE §5, §10).
- Adapted code from a reference repo keeps a header naming the source repo and its license.
- TS: `type` over `interface`, `const Component: FC<Props>`, no one-letter names. Tests use RTL queries and userEvent, and mock only the bindings/IPC layer.
